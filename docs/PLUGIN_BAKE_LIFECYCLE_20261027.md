# 2026-10-27：连接骨烘焙与传输取样修复

本轮修复 Blender 插件，不改变求解器、前端协议或 CPU/CUDA 等后端。原生物理验收与用户的实际裙子场景验收不包含在以下程序化测试结论中。

## 问题与行为

- 连接骨完整烘焙：旧显示映射临时断开连接、关闭刚体骨的缩放继承；烘焙恢复作者设置后，同一矩阵不一定能由关键帧表达。现在仅对作者原本连接的子骨，按作者继承模式生成可表达的姿态：头跟随已映射父骨的尾，Y 长度追随材料尾。横截面可能是单骨 TRS 近似，诊断保留；物理代理和求解器轨迹不被修改。非连接骨保留既有策略。
- 烘焙按父骨优先写入，保留作者 Action、连接及继承标志。完整烘焙仍用原有误差门限验证缓存移除后的实际关键帧；不能表达时拒绝并恢复原输入。单帧采样失败也会恢复骨缓存和作者状态。
- 单帧烘焙会提交基础网格或骨骼 Action，并改变解算组成员。旧会话动画不再对应新场景；现在在 Fetch 修改任何目标前拒绝读取旧会话，也不消费排队中的旧帧。本次重新传输确实完成后才解除保护。标记随工程保存，不通过移除报错来强行获取。
- Single 的普通网格坐标先统一暂存、写入。坐标写入或骨采样失败时恢复已写坐标。缓存拆除后的文件系统/RNA 异常仍可能留下部分输出，会明确报告该边界，不声称跨磁盘完整回滚。
- Transfer 的几何与骨骼参数在同一次作者姿态恢复作用域中编码，避免两个 modal tick 各取不同状态。同步编码失败会恢复该同步过程改动的代理网格、变换、作者记录和质量状态；远端 Build 失败不属于该本地事务。失效绑定的既有 reconcile 清理也不是此事务的完整回滚对象。

## 针对性验证

- Blender 5.1.2：连接链父骨优先烘焙、非均匀缩放、保存重开，最大矩阵误差约 4.77e-7；原有 3e-5 最终验证门未放宽。
- 六种骨骼缩放继承模式、未绑定父骨，以及非连接分支保持既有策略的映射测试。
- 完整插件注册，三根连接骨使用真实 CBOR 磁盘缓存/accept_frame，并配合两个真实 PC2 网格：完整骨动画烘焙与保存重开；Single 后 Fetch 提前拒绝；第二网格写入失败和骨采样失败恢复输入。
- 测试中的 PDRD 测量由夹具合成，未重新运行 native 求解器；上传确认和取消/超时/异常清理使用隔离的传输状态替身，未宣称真实服务器验收。
- 历史 144 骨私有副本连续两次真实编码成功，解码数据相同，单次约 0.4–0.6 秒。人工在旧编码阶段间移动代理，能造成几何与绑定取样不同；这证明跨阶段漏洞，不能证明用户无操作时出现的同类故障就是此原因。
- 真实非法非均匀代理缩放仍被拒绝。独立 frontend 相交夹具仍报 13 个自交；没有关闭自交检查。

## 同批已审查的显示优化

- 视图缓存使用本地网格与实例矩阵；姿态/物体移动不必反复抽取和上传所有代理几何，脏网格单独刷新，仅重绘相关窗口区域。
- 代理编辑器标题定时器静止时不重复设置标题或重绘整个区域；跨场景时检测编辑器所属窗口的变换状态。真实 GUI G/R 完整乱序流程尚未验收。
- 这些显示改动只有功能范围通过：现有 144 骨测试仍记录约 32ms 的 CPU 快照峰值和显示延迟，不能称完全消除卡顿。
