# 2026-10-27 多选骨骼面板的周期性卡顿

## 现场与原因

上一轮空闲回调优化已加载，但用户仍报告流畅与卡顿交错。9876当前为Blender5.1.2，144骨、148对象、POSE；新FPS属性存在。预览队列为空、作者跟随无待办，不能以未重启或永久预览任务解释。

主线程完整采样发现，骨面板每次重绘的“实际物理”多选摘要，对每根骨再次扫描全部对象、骨骼引用与动力学组，形成重复交叉扫描。15次摘要绘制累计约1.7秒，是本轮主要热点。未开profiler时，原窗口20ms探针p95为145ms、最大180ms，3秒内15次超过100ms；仅临时隐藏骨面板后p95为53ms、最大69ms、无超过100ms。面板属性已自动恢复，未保存偏好，用户工程未修改。

## 本轮产品修改

`blender_addon/ui/bone_physics.py`：多选摘要在一次draw内建立归属和组的索引，按原规则判断所有选中骨骼；活动骨原单骨严格入口、实际材质类型、共享代理/重复身份/失配组的判断保留。不跨draw缓存RNA，不修改作者写入、代理跟随、引擎、质量或解算路径；不靠隐藏面板、降低FPS或删除检查解决。

8类真实副本对照通过。经典和双栏真实窗口、鼠标/选择事件及实际骨面板drawer均已运行，私有进程自然退出0。摘要绘制中位数约74ms降到6–7ms，最大值从82–91ms降到9–10ms。最终必要审查PASS。

第一组真实窗口测试处于144代理质量初次计算期间，候选仍有部分超过100ms的事件循环间隔。后续短profile确认其质量队列尚在每tick计算首个体积，这与用户已稳定现场的质量回调不同；不将冷启动队列称为已确认的现场新根因，也不据此擅改质量计算。

暖态补测正常等待19.24秒，144条质量缓存全部完成，GPU连续两次稳定；未禁用或加快初始化。静止3秒无profile：70个20ms探针，p95=65.67ms、max=89.12ms，无超过100ms；摘要71次max=13.90ms。操作3秒仍有5/62间隔超过100ms、max139.16ms，摘要max12.05ms。该结果支持静止周期尖峰改善，但操作延迟仍继续定位；本轮不标整体性能验收完成。
