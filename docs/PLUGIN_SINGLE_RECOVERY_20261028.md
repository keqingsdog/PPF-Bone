# 单帧烘焙后的继续操作与恢复

本次修改仅涉及插件，不需要重新编译引擎。正式安装状态与验证范围见当前工作检查点。

## 为什么原来的面板会全灰

原 Single 会把普通目标移出动力学组并删除其模拟缓存。骨骼侧则提交了单帧 Action、撤下骨缓存。与此同时，已经取回的帧列表仍可能保留，例如界面中的 69 帧。于是“没有可模拟的动力学”和“已有模拟帧，禁止编辑”可能同时成立。仅清空待应用队列不能解决这些已取回状态与物理组的变化。

## 新的网格／骨骼流程

1. 先取回需要的模拟帧，在所需时间点点击“烘焙单帧”。
2. 保存基础网格、作者 Action、模拟缓存位置和已取回帧的恢复记录。动力学组成员和原 PC2 文件保留，冻结显示使用的缓存修改器，并清退旧帧状态。
3. 想回到原模拟并烘焙完整动画，点击“恢复单帧前模拟”；恢复后再点击“烘焙动画”。这不是调用 Blender 的全局 Undo。
4. 想把这一帧作为后续编辑的起点，点击“保留单帧并结束恢复”，再继续编辑或重新传输。

恢复入口在求解器面板中独立显示，不依赖存在普通动力学组。仅有骨骼参与物理的场景也应显示可用操作。

恢复前会检查目标、骨绑定、原 Action/slot、修改器和缓存是否仍对应。绑定代理的网格、组成员、父对象、骨骼父级和父逆矩阵也纳入必要的写前检查。已经编辑过的代理不能套回旧模拟。用户可以选择保留新的单帧结果并结束旧恢复记录，不必陷在无法退出的状态。

## 保留的边界

- 恢复记录保存于工程中；实际 PC2 与骨缓存文件仍须存在。
- 新记录只能覆盖安装新版本后执行的操作。以前已经删除的缓存和未记录的作者状态不能凭空恢复。
- Curve 与含 Curve 的混合 Single 保留原有流程，并明确提示不能使用本次新恢复入口；没有删除原功能。
- 某些动画化修改器、驱动或 NLA 会让缓存自动重新启用，这类情况会在写入前拒绝可恢复冻结。
- 磁盘缓存的 Blender 全局 Undo 仍不是本轮功能。

## 实际证据

私有 Blender 5.1.2 完整插件注册测试使用三根连接骨、真实 CBOR 磁盘缓存和两个真实 PC2 网格。PDRD 测量由夹具合成，不是原生物理解算结果。测试覆盖两份已取回帧列表各 69 条、Single 后清零、保存重开后恢复、实际 Full Bake 操作及其 tick/finalize 六帧闭环。还覆盖纯骨、单对象、作者 Action、缺失骨、修改器变化、代理编辑后失效及保留结果退出。

2026-10-28 最终源码范围审查为 STATUS PASS。直接改变代理父逆矩阵的定点测试同样在写入前拒绝恢复，不修改网格或 Action。

这些结论不代表用户原来的 144 骨现场已经恢复，也不代替 GUI 撤销崩溃或真实服务器测试。
