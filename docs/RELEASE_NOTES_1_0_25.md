# 1.0.25 源码交接

本版保留 PPF 源码及 CPU、CUDA、Metal、ROCm 构建路线，包含插件控制事件、缓存迁移、骨骼与面板显示、单帧烘焙及恢复、路径与默认 FPS、偏好设置和续算更新；原生部分包括 current-anchor、接触统计、checkpoint 与 CUDA 生成器修复。性能优化已取消。

## 已验证范围

Windows 已有 CPU 实际骨骼烘焙、保留烘焙并结束恢复、重新传输与构建，以及完整 CPU 续算的限定证据。正式运行包 CPU 和 CUDA solver 新进程普通短运行已通过；不得外推为所有场景或其他平台通过。Blender 5.1 正式插件路径新进程验证了 1.0.25、偏好路径填空和默认 FPS、单帧烘焙及恢复；自然 GUI 验收尚未完成。

原 plane 复核包已恢复，受控重建结果见下文；fresh 重建仅观察到字节非确定性，同一二进制亦会出现，尚无量化物理误差证明功能缺陷。其他平台保留源码，未据此声称本轮已实跑。

## 操作与构建

续算时增加总帧数、保持起始帧不变，并使用已完成运行保存的 finish state；旧运行缺失该状态时需重新运行。偏好中的本机求解器目录仅填充场景中为空的路径。单帧烘焙后可恢复模拟，或保留烘焙并结束恢复；旧记录若只有相对缓存路径且缺少原工程目录，需回原工程重新烘焙或结束恢复记录。

构建与依赖见 [BUILDING_BONES.md](../BUILDING_BONES.md)；源码包不包含预编译运行时或生成的 CUDA build。实际安装目标和运行证据以交接文档为准。

碰撞组合合同修复：客户端正确接受真实生产者的 cross-link 排除对并拒绝非法输入。host 7 项通过；CPU 运行时 baseline20、parent、PAIR、mask0 四个限定案例各自然退出 0、20 帧有限。斜向 PLANE 仅有 host 证据，不能推断其原生运行已通过。正式插件路径新进程合同冒烟通过。

## PCG 容差与精度限制

界面在 PPF 侧栏的 Scene Configuration（场景配置）→ Linear System Solver（线性系统求解器）→ PCG Tolerance（PCG 容差）。可按场景输入 0.000001；默认值仍为 0.001，原有值保留。该值是 PCG 相对线性残差停止阈值，不保证位移误差。

原复核包恢复后，CPU 的 v5 受控重建中默认误差 26.495 µm，超过实验 20 µm 阈值；仅设 CG=1e-6 为 1.005 µm，仅设最低 Newton=5 为 0.278 µm，均自然退出且 20 帧有限。重建显式使用 air_density=0，原模板不完整，不能声称所有参数与原测试相同。PCG 相对残差符合各自阈值；未建立用户/API 默认 20 µm 合同。本项归档为精度限制，未修改原生求解器或全局默认。
