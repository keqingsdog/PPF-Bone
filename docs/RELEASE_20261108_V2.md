# 2026-11-08 复核 v2 合并说明

本次在 1.0.36 当前源码上整合，未用复核包覆盖整棵源码。完整源码包含此前本机完成的求解器修复与此次插件、Python 前端修复。

## 求解器通用修复

- 空恢复曲线历史缓冲区使用实际 CurveHistory 类型分配，保证所需对齐；零计数语义不变。
- FEM 材料旋转在唯一性成立时支持变形梯度负行列式及 rank-2 过零，使用 proper rotation 和带符号的伸长；不修改实际变形、不取绝对值替换物理输入。
- 原生设备计算、结果姿态发布、冷读取和 Blender 回写采用一致的材料旋转适用域；退化、不唯一、非有限输入仍拒绝。
- 未按场景名、骨名、帧号或故障 lane 添加放行；未调整作者的 E、密度、动作或模型。

这些更改具有独立小例与实际场景证据，不等于对所有可能模型的物理正确性作保证。

## 插件与前端

- 骨骼 rest 浮点漂移：在既定误差范围内，通过 Blender 骨骼转换规则验证动画与父链，统一生成 frame 与 scale，保留原头位置。真实非均匀缩放、剪切、反射、非有限输入仍拒绝；不修改用户骨骼。
- 不再提供硬关节新建入口。旧 BALL_FIXED、HINGE、D6 配置保留识别，导出与相关复制/预设会明确拒绝，必须由用户明确选择软关节。没有将刚体物理体改成软体，也没有把硬连接静默替换为弹簧。
- 修复 CPU producer v2 静态祖先桥接路由，保留作者字段、能力验证和原有 v3 路由。
- 插件传输优化：捕获归属索引、CBOR 分块与磁盘暂存、有界事件日志、上传后的引用释放。原数据身份与传输顺序保留。
- 前端保存优化：文件暂存和原子替换，保持保存图的数组、引用与循环；Windows 失败路径保留旧目标并清理本次临时文件。

## 验证范围

八个宣发场景已经各完成 192 帧解算、动画获取与重新加载验证，八支视频已生成。03 与 04 物理解算使用 GPU，其余六场的物理解算使用 CPU；部分影片采用 GPU 渲染，不能把渲染后端当作物理解算后端。

此次复核合并使用 Blender 5.1.2 及 Windows 前端的小型实际入口测试。静态桥接验证到真实 Transfer、native Build 和 FK，未把这项测试称为完整仿真。矩阵测试使用真实 Blender 转换 API 及构造的骨骼/姿态输入；约束正例尚非用户原约束工程。

复核包没有完整人物工程及 686 MB 原输入，故未复现该人物的 4168 帧完整解算，原作者的矩阵检查记录也不等于本次物理验收。03 宣发镜头展示软体代理变形，未证实上压板接触；原动作保留。

源码中的针对性测试是后续重建依据，不能把未执行的其他测试模块或中断实验记为通过。开发日志保留了失败、中断及成功的区别。

## 大文件读取策略与代价

- 默认在解码前按文件大小选择：不超过 32 MiB 使用原通用读取，超过 32 MiB 使用受保护流式读取。内部 API 可显式指定 legacy=True 或 stream=True，两者互斥；流式错误不会自动转向高内存读取。
- 流式读取接受当前插件产生的 definite、无 tag CBOR。结构预检拒绝嵌套 tag、indefinite、截断和越过首 root 的读取，避免分段解码共享引用造成数据错读；原通用 loads_scene 保持原行为。
- 一个 2.8 MB 中型样本中，tracemalloc 下 Python 峰值从约 19.64 MB 降至 3.59 MB；不启用追踪时读取时间从约 0.035 秒增至 0.680 秒。低内存路径存在 CPU 代价，不能说所有输入都更快，也未外推原 686 MB 工程。默认小文件保留旧路径就是为避免这项日常开销。
- Windows 文件读写、实际 session 对象恢复、循环与数组别名、失败保留旧目标及临时清理均已做针对性测试；真实 03 输入也经 SceneDecoder 实际进入流式路径读取成功。未重跑用户包中缺失的原人物工程。
