# 2026-10-27 插件阶段1：缓存、复制与折叠标题

## 当前用户要求

- 刷新不应长时间阻塞Blender。并行不能通过后台线程读写bpy/bmesh/GPU实现；先减少重复查询、复用GPU批次，再处理CPU采样。现阶段不宣称整体交互已流畅。
- Blender普通复制出的骨架没有有效PPF物理绑定，不得抢占原骨架代理。另有专用“复制骨架与代理”工具复制物理数据。
- 场景参数折叠标题不应同一行显示两遍，保持中文与折叠状态。

## 本地发布内容与证据

1. 单次骨面板draw共享只读选择/活动骨/材质组解析，结束即释放，不跨draw保留RNA。setter/操作始终即时解析，测试在缓存144选择后改为2骨，只写新2骨且保留各自向量其它分量。真实44次完整draw的三类查询各执行一次。完整面板body仍有约24–33ms，不能当作整体流畅通过。
2. GPU shader/batch按视窗和独立几何版本复用；颜色/选择/过滤/显示样式不重传。上传软预算2ms，固定in-flight直到完成，新请求合并为latest，避免持续动画下永远上传不完。owner集合由完整CPU快照独立发布，普通几何缓存失效不代表身份退休。真实Window暖态style/selection额外shader/batch=0，draw p95约3.4–4.0ms，冷上传最大约11.1ms。7项定向测试包含持续版本推进、追到latest、年龄、几何失效与owner退休、GPU状态恢复。CPU整批采样尚待阶段2；事件循环仍测到约100ms，未宣称不卡。
3. 普通复制在已有延迟清理流程中，按全部代理的实际父级和唯一绑定证明原件，只清理独立单用户复制体的骨物理、身份、跨链与草稿；不删除原代理或修改原组。混合/歧义/共享数据不猜。清理事务失败整体回滚。144骨真实窗口复制后立即进入原骨架代理编辑，自然清理恢复144绑定及实际GPU绘制，源身份不变。普通姿态Action保留；启用/身份字段不可动画，切帧后空副本不再启用。Alt-D链接复制不自动单用户化，本轮未支持。
4. 新增`ppf.bone_rig_duplicate`专用工具：独立骨架数据、代理Mesh、PPF材质组及身份；保留真实网格、相对偏移、颜色、关节、实际材质与碰撞参数，重映射内部连接、恢复曲线和Pin。真实encoder验证两架、6绑定、6独占组、2连接。作者Action/外部作者依赖沿Blender通常共享语义保留引用，不能宣称整场景所有资源都克隆。当前solver输出/缓存/播放、代理动画、外部跨架连接明确拒绝；已提交普通Action不按名称猜来源。首次组恢复及晚期异常注入均完整回滚，不残留事务标记。
5. 场景八个折叠箭头显式`text=''`，标题只由原label绘制。真实中文Window中六种折叠/展开与布局调用验证箭头文字为空、标题唯一，普通属性翻译仍保留。未做用户视觉验收。

以上各项必要审查均PASS。失败记录保留：测试器上下文、RNA回调签名、早期回滚与上传饥饿问题先被发现再修复，不以先前失败作为通过证据。
