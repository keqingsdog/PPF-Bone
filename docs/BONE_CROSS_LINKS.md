# 跨骨链弹簧

源码与插件已实现；使用时须配套更新插件和求解器。实际验证状态见[分支验证记录](../VALIDATION_BONES.md)，本文不代替测试证据。

## 用途与操作

骨骼链原有的父子关节保持不变。在不同链的骨骼之间另加横向弹簧，可限制链间被拉开或挤近；增加斜向弹簧可抵抗剪切。这是骨骼布料的近似网络，其细节仍受骨骼数量和代理体形状影响。

1. 先为需要的骨骼创建物理代理，确保它们参与物理。
2. 在同一骨架中选择两根骨骼，用骨骼物理面板的跨链连接创建单对连接。
3. 选择两条或更多等长连续链，可创建平面网络；筒形要求至少三链并连接首尾。可选斜向连接。
4. 在连接列表选择多条连接，批量调整、启用、停用或删除。独立网络预设可以保存拓扑、参数及作者锚点；跨骨架载入时需明确对应骨名。
5. 沿正常PPF流程重新传输、构建并运行。已有模拟输出需要先清除后修改约束。

刚度单位为N/m，值越大，链间距越不容易改变。阻尼单位为N·s/m，值越大，链间伸缩振荡越快衰减。默认值由代理实际体积、有效密度或目标质量计算，不是所有骨架通用的固定刚度。手调值不会被重复创建自动覆盖。

每次传输以模拟起始姿态的锚点距离为零力参考。全局平移或旋转不会凭空产生弹簧力。连接不锁定两根骨骼的相对朝向，也不替代纵向关节的弯曲／扭转设置。

跨链连接保持原碰撞组及相邻骨骼碰撞排除策略。弹簧连接本身不构成关闭碰撞的指令。删除端点后，连接保留为失效记录，需修复、停用或删除后再传输。

## 代码边界

- `blender_addon/models|core|ops/cross_links.py`：持久作者记录、批量事务、预设、面板操作。
- `blender_addon/mcp/handlers/cross_links.py`：复用同一作者逻辑的程序化接口。
- `frontend/_cross_links_.py`：实际PDRD/FEM拓扑形成后，将作者世界锚点绑定到原生局部坐标或四面体权重；写入独立`bin/cross_links_v1.json`。
- `crates/ppf-cts-solver/src/cross_links.rs`：严格协议及原生端点校验，允许独立网络形成环；骨骼父子图验证原位保留。
- 现有SoftJoints批次保留树记录前缀，附加网络记录；恢复力Bundle使用独立的CrossLinkDistance种类，共享求解、步历史和checkpoint接线。

这是轴向距离弹簧，能量和梯度使用同一平滑距离函数。求解Hessian采用PSD/Gauss–Newton近似；不宣称包含刚体旋转的所有精确几何二阶项。阻尼参考应来自接受步，拒绝的候选不得污染历史。

新模型改变设备语义，需按本树原有身份生成和构建流程编译配套后端及求解器。旧求解器必须明确拒绝这一能力，不能静默忽略网络。源码继续保留CPU、CUDA、Metal、ROCm路径；某一平台的编译或测试不代表全部平台已验证。

## 本轮实际覆盖

Windows CPU已运行14个刚体／软体／混合端点及闭环案例、一次非零阻尼checkpoint恢复，以及32骨／80连接的4秒裙子。Windows CUDA已运行相同无跨链薄板静态接触对照及0.6秒裙子，实际加载本机GPU并消费全部80条新连接。GPU短例不代替GPU4秒长例；Linux、Metal、ROCm及其他显卡未在本轮实跑。

演示的刚度和阻尼是为该32骨BOX裙子手调的参数，没有改变插件的全局默认值。链间弹簧限制锚点距离，不会在两条链之间自动生成碰撞面；避免可见裙面穿插仍需要合适的代理形状、链密度和蒙皮权重，不能把提高刚度当作连续布面碰撞保证。
