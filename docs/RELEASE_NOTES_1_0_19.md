# 1.0.19 实时显示修复候选

本版继承 1.0.18 的烘焙、作者动画保护与播放修复，另修正普通刚体代理及链间弹簧线在正常启动顺序下漏掉当前帧显示数据的问题。正式安装与云盘仍为 1.0.17；本候选尚未正式部署。

原流程中，显示处理器可能先于骨骼姿态处理器运行，读不到当前帧完成数据；骨骼稍后更新，却没有再次通知显示层。现在在姿态成功提交后通知显示层，并与原显示处理器共用消费入口。每次成功发布按场景、显示版本、帧及完成序号去重；显示端失败不回滚已经成功的骨骼姿态。动态 PC2 网格继续使用原坐标包路径，没有重排处理器或额外执行依赖图更新。

实际验证范围（Blender 5.1.2，私有 GUI）：

- 解压既有候选 ZIP 后按插件正常入口注册，三帧复现显示先于姿态的原顺序；旧版两普通代理和 409 条连接线没有当前帧发布。
- 修后相同三帧的两个普通代理矩阵及连接端点与姿态完成数据独立计算结果误差为零；实际绘制入口恢复连接线 GPU 批次。
- 142 个动态 PC2 代理的 GPU 资源可用，坐标和世界矩阵与独立求值网格逐项误差为零。
- 重复完成通知不重复合成，同帧新完成序号可以刷新；注入显示观察器异常后，核心姿态完成数据保留，失效显示发布撤销。测试进程自然退出 0。

该补丁及上述运行证据已经高级审查通过。新 1.0.19 ZIP 已在私有扩展仓库通过实际安装和启用：插件、显示模块、姿态模块及 cbor2 都从私有扩展位置加载，实际配置和临时目录先行断言。正常处理器顺序下三帧共 24 次实际绘制调用恢复两普通代理及 409 条连接线；142 个动态 PC2 代理的坐标和世界矩阵对照误差为零，无绘制错误，进程自然退出 0。这是定向安装与运行证据，不是截图或所有场景的视觉验收。该测试临时关闭了两个代理的 PC2 来覆盖普通刚体显示分支，不能作为原 144 动态代理场景的性能计时。

正确显示后的轻量计时使用原场景 144 个动态 PC2 代理及至少 408 条真实链线，GPU 开启，预热一秒后测三秒：57 帧，中位间隔 52.74 毫秒、P95 57.75、最大 66.77。每帧都有姿态完成、显示发布及非空连接线，进程自然退出 0。先跑的一次相同轻量测试未记录逐帧发布，原记录保留；此处采用补齐逐帧记录的后一次结果。该计时仍约 19 FPS，不能称性能问题已解决，也不能与漏画链线的旧结果直接作同条件对比。

未烘焙播放性能仍开放。双进程规划只在私有原型测试，未包含在本版；固定测试场景中的吞吐提升不能外推成所有场景的性能保证。旧 1.0.18 的 GPU 开启计时也不能代表本次恢复普通代理及弹簧线后的完整绘制成本。硬球关节和原生 Undo 崩溃继续按用户决定暂缓，按权重生成代理仍是待办。其他测试范围与限制见 [1.0.18 版本说明](RELEASE_NOTES_1_0_18.md)。
