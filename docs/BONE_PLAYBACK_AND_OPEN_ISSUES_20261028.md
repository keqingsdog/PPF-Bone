# 骨骼播放驱动与未完成项，2026-10-28

未烘焙时，求解器输出代理/材料框架，插件按绑定凭据映射成骨骼姿态缓存。rigid_pose的frame_change_post处理器读取对应帧、计算父子坐标与连接投影，写PoseBone.matrix_basis；这不是逐帧Action关键帧，也不是用普通网格MESH_CACHE直接驱动骨骼。完整烘焙再把采样写成Action/F-Curve。

普通Mesh通过PC2和Blender原生MESH_CACHE修改器显示。骨骼当前额外经历Python缓存读取、映射与姿态写入，并触发骨架依赖图。该主线程路径确有额外工作；现有功能正确性测试没有量化用户场景卡顿占比，不能声称实时回传性能已优化完。文件读取/数值准备与最终RNA写入的拆分属于后续明确性能任务，不在本轮假装完成。

实时跟随按新帧到达推进，球接触等高接触压力可降低全场产帧速度；后端仍按f/fps对固定模拟时间插值输出。墙钟等待不是物理帧的变速。完整动画按设定FPS播放时应另行核验，不用到帧预览直接判断重力变化。

Clear Local会调用clear_bone_pose_cache并清理未烘焙骨骼/普通缓存显示。已烘焙Action是保存结果，和未烘焙cache不是同一对象。撤销本地烘焙/恢复模拟为插件显式事务入口，保护原数据及作者间隙修改；不是承诺普通Ctrl-Z能恢复所有磁盘与原生状态。

后续验证已覆盖特定范围：Outliner 在 Blender 5.1.2 的生产回调中收起目标 root 与 Empty，同时保留原展开状态及无关对象；长场景观察器中断后通过真实 server GetAll 恢复，不能将这两项笼统列为完全未验证。恢复记录包含观察器故障，构建和求解的精确耗时不可得。

仍有证据缺口：用户复杂长裙完整场景、任意 Undo 崩溃根除、实时跟随卡顿优化，以及 GPU 混合骨代理显示。用户反馈 1.0.17 中已烘焙和未烘焙状态的绿色盒体错位且卡顿，显示验收已重新打开，修复及用户场景验证尚未完成。已有单 FEM 代理和长场景的测试只证明各自测试范围，不能外推为这些问题全部解决。用户此前编辑跟随现场确认未解算，不能把该问题归因模拟缓存。三文件模式切换补丁有定向实际事件循环与编辑预览测试，仍不等于所有交互都已验收。
