# 1.0.21 修复说明

本次处理对 1.0.20 源码和插件复核中报告的路径、工作流及旧测试问题。A/B、C、D 和 E06 已通过各自范围的高级复审；最终安装及交付状态以随包回执为准。

- 源码运行配置区分解释器入口和解析目标，并保留运行目录闭包检查；构建用虚拟环境与可分发运行时的说明分开。launcher 生成到子进程启动沿用冻结入口与 canonical 目标，含新旧命令的重定向保护。Windows 模拟 POSIX 路径、内部链接、外部目标拒绝、迁移和身份变化等专项按其实际范围验证；真实 Linux/macOS 原生构建和求解尚未因此通过。
- 工作流生成模板、Docker／扩展发行入口与授权边界已整理；当前工作树的 47 个实际工作流通过 actionlint。正常生成覆盖 21 个 Linux 与 21 个 Windows 示例。未触发远端工作流，仓库 environment、实际审批和云角色 trust 仍需在目标环境确认。
- 三项 Transfer 回归测试适配当前原子编码和上传两个阶段，保留场景、连接身份、ticket 与取消边界；胶囊测试允许作者阶段相交并检查有效闭合网格和骨骼编码。四项在私有 Blender 5.1.2 和 Goo 4.3.2 各自然退出 0，Goo 4.3.2 的 trace 分支也通过。Transfer 测试的网络和编码传输使用替身，不代表真实远端求解通过。
- 报告点名的五份公开文档已将开发机绝对路径改为占位或相对说明；保留历史失败和未验证范围。这不是对所有公开资源、历史或第三方许可的完整审计。

源码保留官方 CPU、CUDA、Metal、ROCm 后端与构建路线；平台支持和构建结果仍以各平台实际运行证据为准。P05 的 Blender 5.x timer 上下文是待验证风险，不能说已经确认故障或全部关闭。硬球关节与原生 Undo 崩溃按用户决定暂缓，CUSTOM 回滚已交 Linux 检查，按权重生成代理仅列待办。已有缓存的磁盘恢复限制仍应遵循对应功能说明。

早期测试曾写入用户偏好，缺少事前副本，影响范围未知；另一次 GUI 测试使用系统临时目录写入 `quit.blend`，是否覆盖原退出恢复未知。后续验证使用独立配置和临时目录；事故文件不加入分享包。
