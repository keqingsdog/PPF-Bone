# 2026-10-27 添加大量骨骼代理后界面卡顿

## 原因与修改

现场为 Blender 5.1.2、144 根骨骼、145 个网格，未播放、未解算。主线程短采样确认重复归属验证、组查找、GPU 网格提取和缓存按钮 poll。CPU/GPU 总占用正常不能排除 Python 主线程卡顿。

- `core/bone_author_follow.py`：空闲只比较当前矩阵/静止长度；存在变化时重新执行严格归属验证，写入路径保留原严格验证。
- `ui/bone_overlay.py`：GPU 数据快照按变化失效；空闲不重复提取网格、不强制重绘。保留 primitive-only draw 和 Undo/load 的身份隔离。
- `ui/bone_physics.py`：GPU 显示区新增“共享刷新 FPS”，1–60，默认30。多个启用场景采用最高设置；这是采样频率，非解算步长或时间轴帧率。
- `core/pc2.py`：没有任何内存/磁盘静态形变缓存时，缓存按钮直接返回空，不逐对象证明不存在缓存的归属。存在候选时保留原严格归属门；扫描失败回原门，兼容 Windows 大小写扩展名。

## 功能与性能证据

同一个现场另存副本，在独立 Blender 进程中测试；未改用户原工程、未重载正在运行的插件。

| 同进程直接测量 | 修改前 | 修改后 |
| --- | ---: | ---: |
|20次空闲骨骼同步检查|1.619秒|0.176秒|
|20次空闲GPU检查|0.972秒、2880次几何采样|0.0148秒、0次几何采样|
|10次空缓存按钮poll|1.140秒|0.000723秒|

这些是具体回调耗时，不代表整个 Blender、解算器或活动编辑速度的同倍提升。

真实副本验证：姿态/物体变换跟随、编辑模式骨长预览和提交、选择/颜色更新、启用和禁用GPU、视图层/场景切换、无效归属和禁用组不进入写入。PC2真实归属的内存/磁盘候选及foreign拒绝通过。回调10项、缓存poll9项直接测试通过，双场景5/60FPS共享行为通过。最终审查 PASS。

测试脚本第一次跨编辑模式保留了旧 Bone RNA，触发测试进程AV；修正测试为重新按名称取得Bone后重跑通过。此失败未用作产品通过证据。仅调用生命周期回调并验证快照清理，未验证真实GUI撤销；不声称修复原Undo AV。未新增多版本全矩阵或长程求解。
