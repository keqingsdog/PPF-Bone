# 1.0.18 播放与烘焙修复候选

尚未发布。实际候选ZIP已通过私有Blender 5.1.2安装与三帧烘焙／第40帧恢复验证；未烘焙播放的性能问题仍开放，不能把候选或限定测试作为全部完成证明。

关闭 GPU 显示仍卡顿的原因已分开定位：旧作者跟随把动画求值当作作者修改，反复启动同步；旧软体完整烘焙又为每个采样生成一条形态键权重曲线。关闭绘制不会停止这两条主线程工作。

候选把纯姿态／骨架物体动画求值与作者 rest、代理局部变换等编辑分开，播放不写代理；作者确认移动、缩放等操作仍可同步，取消操作不留下待处理工作。显式 Transfer 仍执行完整同步。身份重建期间不采样观察值。

普通骨代理的显示位置使用当前评估骨骼及持久绑定偏移；动态 PC2／形态键代理使用与当前视口、帧及网格版本匹配的坐标包。同帧数据更新使用独立递增发布序号，旧坐标和旧拓扑不会混用。动态上传先准备整包再绘制；Blender Python GPU 缓冲绘制后不能再次填充，所以每帧新建顶点缓冲并复用索引缓冲。

完整动画烘焙仅在对象没有作者形态键、由插件新建 Key 时使用绝对形态键和一条 eval_time 曲线，保留采样帧、子帧保持和范围外 Basis。已有作者形态键／Action 使用原兼容路径，Curve 和单帧烘焙不因该优化改变。已保存的旧烘焙数据不会自动迁移；重新烘焙才能得到新的曲线编码。

作者在烘焙期间修改 UV、材质、形态键坐标或曲线时，操作拒绝覆盖。纯预检失败与部分提交失败分别处理，保留作者编辑、已有采样输出和可用 PC2；安全恢复事务支持保存后在新进程及其他帧恢复。

源码分发的 v2 定位配置按各后端记录真实可执行文件和库位置，修正 CPU／CUDA／Metal 切换时猜错目录的问题。旧 v2 原后端配置兼容，未配置的后端明确拒绝；v1 仍限 Windows／Linux CUDA。Linux/macOS 的本机原生构建和运行没有因此被宣称通过。

实际验证范围：

- Blender 4.2.0、Goo 4.3.2、Blender 4.5.0、5.1.2 的真实 PC2 完整烘焙／跨帧恢复及独立重开；旧作者 Action、间隙编辑及故障回滚另有 5.1.2 定向测试。
- 5.1.2 私有 GUI 的 144 PC2 代理和一个合成形态键、同帧 PC2 覆写、两视口 owner 局部视图、选择／颜色／显示开关及拓扑／非有限值／上传失败测试。它们不是所有 modifier 或所有 View Layer 的穷尽证明。
- 1801 帧长场景工作副本，两个软球经生产路径重烘焙，原骨骼 Action 保留；与旧结果逐帧和子帧对比世界顶点最大差 2.403e-7 m，独立重开抽样一致。没有重新求解该长场景。

保留边界：硬球关节及原生 Undo 崩溃按用户决定暂缓；按权重生成代理仅待办。真正无法以 TRS 表示的剪切仍会拒绝；XYZ 接近 90° 的误报已作定向修复。非 PC2 修改器保留原显示回退路径，不同 View Layer 尚未专项实测。

测试隔离记录：早前 CLI 安装曾写用户偏好，没有事前副本，不能承诺完全恢复；本轮早期 GUI 测试又因遗漏 TEMP/TMP 写入系统临时 quit.blend，未知是否覆盖先前退出恢复文件。后续测试在插件导入前断言实际 CONFIG、环境 TEMP/TMP 及 Blender 临时目录均为私有位置。事故二进制不得加入分享包。

Linux 反馈 P01 逐骨手动关节帧和 P03 碰撞排除不覆写颜色经 Blender 5.1 实际 RNA 定向测试；E09 后端路由测试的求解器回复为模拟值，不能代替 Linux/macOS 原生运行。

## 当帧发布缺口（待修）

正常注册顺序可能使 overlay 帧回调先于骨骼姿态完成回调；普通刚体代理和链间连接线因此可能缺少当帧 publication 而不显示。已完成的动态 PC2／形态键专项证据仍在其测试范围内，但不能说明原生 GPU 同帧显示整体通过。当前缺口正在修复，须完成实际显示及回归验证。
